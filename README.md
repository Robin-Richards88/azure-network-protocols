# Network Security Groups (NSGs) and Inspecting Traffic Between Azure Virtual Machines

This project uses **Microsoft Azure virtual machines**, **Wireshark**, and common command-line tools to observe network traffic and demonstrate how Azure Network Security Groups control communication between systems.

---

## Project Objective

The goal of this lab is to connect networking concepts to a working cloud environment. Rather than only reading about protocols and firewall rules, the lab focuses on observing traffic directly, testing connectivity, and seeing how changes to an NSG affect communication between virtual machines.

## Environments and Technologies Used

- Microsoft Azure (Virtual Machines / Compute)
- Azure Network Security Groups (NSGs)
- Wireshark (Protocol Analyzer)
- Remote Desktop
- Windows command-line tools
- Windows 10
- Ubuntu Server 20.04

## Network Protocols Observed

- ICMP
- SSH
- DNS
- HTTP / HTTPS
- Remote Desktop Protocol (RDP)

---

## High-Level Workflow

1. Create and access virtual machines in Microsoft Azure.
2. Use Wireshark and command-line tools to inspect traffic between systems.
3. Generate traffic using common network protocols.
4. Modify Network Security Group rules and observe how the changes affect connectivity.
5. Compare expected behavior with the packets and connection results observed in the lab.

---

## Actions and Observations

### 1. Establish the Azure Environment

The lab begins with virtual machines running in Azure. The systems provide endpoints that can be used to generate, capture, allow, and block network traffic in a controlled environment.

### 2. Inspect Traffic with Wireshark

Wireshark is used to capture packets and identify the protocols generated by different actions. This makes it possible to connect a user-facing action, such as testing connectivity or making a network request, with the traffic that actually crosses the network.

### 3. Test Connectivity

Command-line tools are used to generate and troubleshoot traffic between the virtual machines. The results help confirm whether the destination is reachable and whether a protocol is being permitted or blocked.

### 4. Apply Network Security Group Rules

Azure Network Security Groups function as traffic filters for Azure resources. By changing an NSG rule and testing again, the lab demonstrates the relationship between a security rule and the resulting network behavior.

### 5. Verify the Result

After each change, connectivity is tested again and the traffic is reviewed. This reinforces an important troubleshooting habit: verify the result after making a configuration change instead of assuming the change worked.

## Key Takeaway

This lab demonstrates how cloud networking, packet analysis, and access-control rules work together. It also reinforces a practical troubleshooting process: generate traffic, observe the result, change one control, test again, and verify the outcome.
